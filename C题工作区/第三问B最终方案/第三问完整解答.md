# 角色 B：联合场景前瞻（Joint-Scenario One-Step Lookahead）

## 交接摘要（150 字）

角色B：K=64联合场景一步前瞻，按族分层抽样，逐候选以截止期生存贪心推至终局，按按时权重均值选动作，时钟/前驱/预算/H截尾/αβ按正式引擎处理。标称90.96%（98.75/89.44/84.69），较基线+5.87pp，配对CI[4.35,7.27]pp，五映射全胜；环境留出+0.59pp，K=64含选择偏差。

---

## 1. 假设

1. 仅用首任务工期分位 + 期望时间贪心尾部，会低估跨任务工期相关性、H 截尾和链式失败对后续按时权重的影响；用 K 个**联合**未来场景把基准策略推到终局，能更准确地估计每个候选首动作的真实期望。
2. 场景抽样的方差会直接污染“取最大估计值”的决策（winner's curse）；分层抽样可在不增加 K 的情况下显著降低决策噪声。
3. 只有在时钟、前驱解锁、预算、H 截尾和 α/β 映射全部正确的前提下，场景价值才可信；任何“把概率当确定完成”的近似都会把不可达的后继价值算进来。

---

## 2. 方法

### 2.1 输入与合法性

策略只读取 `Engine.observe()` 的公开字段（`time, zone_xy, cost, B, H, alpha, beta, jobs`）、train 划分的族时长池和实例内反馈历史。**不读取**隐藏时长、案例号、目标值，也不读取 validation/test 结果。动作始终 `reserve=0.2`，不使用付费观察（`observations=0`），与基线一致。

### 2.2 工期信念

与 v2 参考实现同源的 128 点离散混合：

```
prior_count = round(128 * 20 / (n_family + 20))
grid = [global_quantiles(prior_count), family_quantiles(128-prior_count)]
再按 feedback_strength=3 用已完成任务的 d_hat 替换一部分分位点
p = alpha * d + beta
```

`d_hat = (completion - service_start - beta) / alpha`，按 family 累积。`feedback_strength<=0` 的语义是“不使用反馈”。这是离散近似，**不声称精确保留任意混合权重**。

### 2.3 联合场景抽样（K=64，主配置）

每个决策点，对所有“尚未尝试”的任务（含未释放任务）独立抽取 K 个工期：

- 对每个族生成 K 个等概率层 `u_s=(s+U_s)/K`，映射到该族 128 点信念网格；
- 每个任务独立置换层序，保证**边际分层**且任务间不产生人为正相关；
- 同一决策点的 K 个场景对所有候选首动作共享（common random numbers），降低候选间比较方差；
- `numpy.random.default_rng(20261122)` 固定，`scenario_seed` 已写入 `summary.json`。

### 2.4 一步前瞻与基准策略

候选首动作 = 当前可行任务（release、前驱、预算、H 可行）+ 等待到下一释放时刻（若有）。

对每个候选 `a` 与每个场景 `k`：

1. 执行 `a`：`s = t + D + 0.5`，`C = s + p`，`t' = min(H, s + max(p, 0.2))`；
2. 以**截止期生存密度贪心**为尾部基准策略，逐任务推进到终局：
   `score(j) = [ w_j * P(p_j <= due_j - start) + Σ_child w_c * P(p_c <= due_c - start - E[p_j] - travel) ] / (D_j + 0.5 + E[p_j])`
   其中子任务项是一步闭包近似，只用于尾部动作排序；价值累计严格用场景实现值；
3. 场景中任务只有 `C <= H` 才算完成并解锁后继；`C > H` 的任务保持 attempted、不解锁任何后继；
4. 预算在排序前筛选（`cost + 2 + 0.1*0.2 + 0.2*D <= B`），不会“选中后再终止尾部”；
5. 无可行任务时，只等待到“前驱在该场景已完成”的任务的下一次释放；没有可达释放则终止该场景。

候选价值 = K 个场景的按时权重均值。选择规则：价值最大 → 执行优先于等待 → due 早 → job_id 字典序，保证确定性。

### 2.5 正确性契约

| 审计项 | 本实现 |
|---|---|
| 时钟 | `t' = min(H, start + max(p,0.2))`；完成时刻 `C = start + p`，移动/准备只计一次 |
| 链式概率 | 用场景实现值：`C>H` 的任务不解锁后继；不再把概率当确定完成 |
| 预算 | 先筛不可负担任务，再按价值排序；尾部不会因预算中途终止 |
| H 截尾 | 所有 `start/C/t` 检查都用 `H`，时钟封顶 `H` |
| α/β | 所有场景时长先映射 `p=αd+β`，再做生存/时钟/预算判断 |
| 分位网格 | 128 点离散近似，不声称精确权重 |
| 合法性 | 仅用 `observe()` 公开字段；`reserve=0.2`；`observations=0` |

### 2.6 复杂度

根并行 rollout 把 `(候选, 场景)` 压成 `(A,K)` 数组，内层对 `n` 个任务向量化。验证集单次运行（一个 case/seed/mapping）平均 **0.0825 s**；v2 参考为 0.1732 s，基线为 0.0063 s。

## 6. 失败分析与历史对比

### 6.1 历史简单 rollout 为什么没超基线（代码级）

历史 `rollout_policy.py` 的 `choose` 与本实现的差异：

1. **时钟**：`times[execute]=min(end,H)`，没有 `max(p,0.2)` 的预留地板；`p<0.2` 时会把下一个任务提前。
2. **空转**：`idle` 对所有未尝试任务的 release 取最小，不检查前驱是否在该场景完成；会等一个永远不可达的后继直到 H。
3. **信念**：默认 `prior=0`，有反馈时直接用反馈小样本，方差大；没有 128 点 prior+feedback 混合。
4. **尾部价值**：`2*prob - prob_delayed` 的近似 + 点估计闭包；没有把“完成概率”和“按时概率”分开。
5. **抽样**：128 个 iid 场景，未分层；候选间虽共享 draws，但决策噪声仍大。
6. **完成/按时**：用 `(reward.mean(), completion.mean())` 字典序，次要目标可能改变首动作。

这些问题会系统性地高估“先做短任务、后做长任务”的价值，并在长工期族（L）和链式案例上放大。历史结论“未超基线”与这些机制一致。

### 6.2 本实现的差异

- 时钟严格 `start+max(p,0.2)`，完成严格 `start+p`；预算先筛；H 封顶；链式失败用场景实现而非概率。
- 截止期生存密度 + 一步闭包的基准策略，在 K=64 下比密度/deadline 基准高约 0.8–1.4pp（五映射）。
- 分层联合抽样 + 固定 `scenario_seed`，决策更稳。
- 空转只等“前驱在该场景已完成”的任务；无不可达空转。

### 6.3 对 v2 参考实现的一个代码观察

`v2_reference._greedy_tail` 中，任务执行后立即 `remaining.discard(jid)`，而子任务只有在 `preds[jid] <= done` 时才被考虑；因此祖先链门控循环里的 `if a in remaining` 恒为假，`pcomp` 实际上没有乘到子任务价值上。也就是说，该实现的“祖先链完成概率门控”在代码层面是空操作，链式失败仍被当作确定完成。这可能是它在 S2/S3 链式案例上低于本实现的原因之一；本报告只把它作为对照观察，不据此否定其 90.24% 的实测结果。

### 6.4 本实现的失败模式

- 标称最小种子差 **-3.47pp**（30 个种子里 3 个为负），出现在长 L 工期抽样到高分位、且链式后继被连带推迟的种子。
- 环境留出 fold0 为 -0.625pp，S3 留出 -1.09pp：说明“联合场景 + 生存基准”的优势依赖训练族池与验证环境的匹配；换环境后，长尾工期和预算结构变化会削弱收益。
- K=16/32 的非单调说明：即使价值估计更准，离散首动作选择仍会被少量场景翻转；K=64 是当前网格内的折中，不是收敛保证。

## 7. 局限

1. **选择偏差**：K=64 是验证集上按 max-K 规则选出的主配置；90.96% 不是无偏效果。K=128 标称更高但五映射更低，说明“选 K”本身有不确定性。
2. **留出弱**：环境留出仅 +0.59pp（CI 含 0），S3 留出为负；不能把验证集增益直接外推到新环境。
3. **信念模型**：128 点离散混合 + 位置不变的反馈替换；没有建模族内异方差、环境漂移或任务级特征（特征为空）。
4. **一步前瞻**：每个决策只前瞻一个首动作，尾部用贪心基准；不是递归最优。基准策略的闭包是一步点估计，不是精确联合概率。
5. **场景独立性**：同族任务按 iid 抽样；若真实数据存在同环境/同批次相关性，联合分布会被低估。
6. **未使用付费观察**：`observations=0`；在长 L 任务上，观察可能改变风险结构，但本方法未评估。
7. **完成率次要**：价值只累计按时权重；完成率虽报告（95.28%），但不是优化目标，某些种子可能以完成率换按时率。
8. **未读 test**：全部结论基于 validation 与 train 环境留出；test 划分从未读取。
