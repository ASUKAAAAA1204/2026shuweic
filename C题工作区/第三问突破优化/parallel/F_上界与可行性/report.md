# 角色 F：上界与可行性 —— 6% 相对提升（≥90.198%）是否可达

> **交接摘要（约 150 字）**：本单元在 `confirm_lookahead.py` 的同一协议下重算了完美信息最优。标称三案例均值：基线 85.0926%，精确 oracle **95.7292%**（证明 90.198% 落在可达域内，余量 +5.53pp），可证明松弛上界 98.4491%。合法在线策略 `lookahead_s40` 达 **90.7986%**，配对 +5.7060pp（95%CI 4.3747–7.0023），五映射逐一不劣，环境留出均值 +0.1042pp（偏弱）。剩余在线差距（oracle−合法）4.93pp 全部集中在 S2/S3，落在非链、交期余量 40–60s 的任务上。**结论：6% 可达（oracle 与合法策略均越过门槛），但 S2/S3 单案例仍未达标，留出证据薄弱。**

---

## 0. 结论（一页）

**判定：可达（attainable），但需分两层表述。**

1. **信息论层（上界）**：完美信息精确最优在标称协议下为 **95.7292%**（S1 99.3750 / S2 95.0000 / S3 92.8125）。由于任何合法策略在每条样本路径上都不优于 oracle，其期望被 oracle 路径逐点支配，因此 **90.198% 严格落在可达域内**，理论余量 **+5.531pp**。这不是"是否可能"的猜测，而是精确最优给出的可证明结论。
2. **构造层（合法下界）**：一个不读隐藏时长、不读案例号、只依赖公开分布与已观测反馈的合法在线策略 `lookahead_s40` 在标称协议下达到 **90.7986%**，已 **高于 90.198%**；配对差值 **+5.7060pp**，按种子 bootstrap 95% 区间 **[4.3747, 7.0023]**（下界 > 0）；五种映射逐一不劣于基线（最小 +2.4769pp）；环境分组留出均值 **+0.1042pp ≥ 0**。按任务书五条门槛逐条对照，均满足。

**但是**（避免过度声称）：
- 标称 avg3 达标主要由 S1（98.96%，接近饱和）拉动；**S2 为 89.1667%、S3 为 84.2708%，单独看仍低于 90.198%**；
- 环境留出虽然均值 ≥ 0，但 **fold0 为 −3.5069pp、fold1 为 +3.7153pp**，符号相反，统计上与 0 不可区分；
- `lookahead_s40` 的参数由其他工作单元在同一 validation 上选定，其点估计带有选择偏差（见 §7）；本单元只做复现与上界，不对其做无偏效应声明。

因此本单元的口径是：**"6% 在原理上可达，且已有合法策略在标称协议上越过门槛；但 S2/S3 的在线差距仍大，环境泛化证据不足，故不能据此宣布稳健突破。"**

## 1. 假设（与正式引擎逐条对齐）

| 项目 | 取值 / 依据 |
|---|---|
| 决策时钟与开工时刻 | 引擎先校验 `release_s <= time`，再令 `s = time + D + 0.5`。故给定时钟 `t`，最早开工为 **`max(t, r) + D + 0.5`**（不是 `max(t+D+0.5, r)`）。这是本单元修正并三方交叉验证的关键语义。 |
| 完成与后续时钟 | `C = s + p`，`p = α·hidden + β`；下一时钟 `t' = s + max(p, b)`。 |
| 预留 b | 完成与按时判定都不依赖 b；b 只进入费用 `2+0.1b+0.2D` 与计划时域 `s+b<=H`。故对"按时率"目标，**b=0.2 支配**（更大 b 更贵且更紧）。 |
| 预算 | 本题所有案例中预算恒不约束：`n·2.02 + 0.2·总行旅 ≤` S1 29.56 < 32、S2 29.56 < 34、S3 39.43 < 40。数值上 oracle 回放费用 24.01 ≪ B。 |
| 前置依赖 | 只有 `completed`（`C<=H`）的任务才解锁后继；censored 不解锁。 |
| 信息边界 | oracle 读取隐藏时长（仅用于评测上界，**不是合法策略**）；合法策略只读 `observe()`（含公开的 α/β）与分布池。 |
| 拟合/采样 | 时长池仅来自 train；隐藏时长逐字复用 `hidden_for`（`random.Random(seed)`，按 `jobs_for` 顺序，在 validation&eligible 池内按 family 取样）。未读取 test。 |

## 2. 方法

### 2.1 完美信息 oracle（精确）
`code/oracle.py::solve_oracle_dp`：状态 `F[mask,last] = 最小时钟`，转移
`s = max(t_prev, r_j) + D + 0.5`，`C = s + p_j`，可行性 `s+0.2<=H and C<=H`；非"迟到祖先"任务额外要求 `C<=due`。由于非祖先任务迟到既无收益也不能解锁，只有祖先允许"迟做解锁"，故对祖先集合枚举 `L`（迟到集合）并对 `L` 扣除权重，取最大——这是精确的，不是启发式。

**三重独立验证**（`code/`，可复跑）：
- DP vs 独立穷举（S1 全部 150 个实例）：`max_abs_diff = 0.0`；
- DP vs MILP（S1 全部 150 + S2 样本 4）：`max_abs_diff = 0.0`；
- DP 计划经**正式 `engine.Engine` 回放**并用 `engine.independent_metrics` 复核：逐实例断言 `invalid_actions==0`、`|engine_rate − DP| < 1e-9`、`cost<=B`；全协议最大独立计分差 **1.14e-13**。

> 曾出现的偏差：早期用 `s=max(t+D+0.5, r)` 建模，导致 DP 值 0.9583 而引擎 0.8333（S2 某实例）。修正为 `max(t,r)+D+0.5` 后三方一致，故上述数字可信。

### 2.2 可证明松弛上界
`code/oracle.py::relaxation_ub`：对任意按时集合 T，仅用必要条件立 MILP 最大化权重——
- 资格：`r_j + D0_j + 0.5 + p_j <= due_j`；
- 截止阈值容量：对每个 `d`，`{due<=d}` 内 `Σ(p_j+0.5) <= d`；
- 释放窗口容量：对每个 `[a,b]`，`{r>=a, due<=b}` 内 `Σ(p_j+0.5) <= b-a`；
- 预算下界：每执行一任务至少 2.02。

该集合忽略顺序与行旅，故 **UB ≥ oracle**（逐实例断言）；它无需优化证明，但更松。

### 2.3 在线可获下界（合法策略）
`lookahead_s40` = 官方 `lookahead_policy.select(strength=40, feedback_strength=3, quantiles=5)`，即 `confirm_lookahead.py` 的同一方法；本单元在自己的 harness 中独立运行，**逐位复现了官方发布值**（标称 90.7986%、五映射 87.5185%），这同时验证了协议一致性。另记录 `v2_s20`（角色 A 的 depth=1/strength=20）作对照。

### 2.4 统计
配对差值以 `(case,seed,mapping)` 为配对单元，先按种子对三案例取均值，再对 30 个种子做 4000 次 bootstrap 求 95% 百分位区间。

## 4. 消融

### 4.1 "迟做解锁"的价值（oracle 内部）
禁止祖先迟到（`allow_late=False`，即所有执行任务都必须按时）后，oracle 仅从 95.7292% 降到 95.6597%，**损失 0.0694pp**（S1 0、S2 0、S3 +0.2083）。说明本题链式结构较松，完美信息最优几乎不需要"牺牲祖先按时性去解锁后代"。

### 4.2 松弛上界的紧度来源
累积加入必要条件后的标称 avg3：

| 约束集合 | avg3 (%) |
|---|---:|
| 仅资格（+预算） | 100.0000 |
| + 截止阈值容量 | 98.4491 |
| + 释放窗口容量 | 98.4491 |
| + 预算（已含） | 98.4491 |

紧度几乎全部来自**截止阈值容量**；释放窗口在当前释放时间分布下不再收紧，预算恒不约束。UB 与 oracle 的剩余 2.7199pp  slack 全部来自被忽略的顺序与行旅。结论：该松弛足以做健全性检查，但**太松，不能用来判定可行性**；判定依赖精确 oracle。

## 6. 失败分析：剩余差距在哪类任务

以 oracle − `lookahead_s40` 的"漏按时权重"分解（标称映射，逐 job，按权重）：

| 案例 | 在线差距(pp) | 主要 family | 主要 zone | 交期余量(due−release) |
|---|---:|---|---|---|
| S1 | 0.417 | A 100% | Z3 100% | 40–60s 100% |
| S2 | 5.833 | **L 58%**, A 28%, P 14% | Z2 40%, Z3 24%, Z4 24% | 40–60s 64%, 20–40s 24% |
| S3 | 8.542 | **A 54.5%**, L 23.2%, P 22.3% | Z3 39.3%, Z4 26.8%, Z2 23.2% | 40–60s 66.1%, 60–80s 23.2% |

合并口径：family A 47.3% / L 33.3% / P 19.4%；zone Z3 35.8% / Z2 27.9% / Z4 25.5%；**非链任务占 90.3%**，链上任务仅 9.7%；交期余量 40–60s 占 66.1%。

要点：
- **差距不是"前置链"造成的**（90% 漏按时任务不在链上），而是**多任务争用同一时间窗**导致的排序/取舍损失；
- S2 的缺口集中在 **family L**，S3 集中在 **family A**，且都落在 **Z3/Z2/Z4** 与 **40–60s 中短余量**任务上；
- S1 已接近饱和（差距 0.42pp），提升空间只在 S2/S3。

## 7. 选择偏差与报告纪律

- 本单元**未选择任何参数**：`lookahead_s40`、`v2_s20` 的配置由其他工作单元在同一 validation 上确定；它们的点估计继承该选择偏差，本报告只把其作为"合法参考/构造性下界"陈述，**不当作无偏效应**。
- oracle 与 ub_relax 不依赖 validation 上的策略选择（oracle 读隐藏时长，UB 只用必要条件），因此对"可达性"的判定不受策略选择偏差影响。
- 所有数字均来自本目录 `results/trials.csv`（2250 行 = 3 案例×30 种子×5 映射×5 方法）与 `results/summary.json`；未引用任何未独立核验的他人数字（包括 93.77% 的旧 oracle 上界——本单元已用 95.7292% 取代）。
- `trials.csv` 中 `ub_relax_knapsack` 行的 completion/cost/observations 为空，是因为该行是解析上界、未做仿真；不是缺失数据。

## 8. 局限

1. **单点划分**：仅 30 个 validation 种子，配对 CI 宽度约 ±1.3pp；对"是否稳定 ≥ 90.198%"的判断在边界附近（+0.60pp）仍偏脆弱。
2. **目标口径**：90.198% 是**三案例 avg3**；S2/S3 单独未达标，avg3 达标由 S1 拉动。若验收改为"每案例均达标"，结论将变为**未达成**。
3. **环境留出偏弱**：均值 +0.10pp、两折反号，不能支撑"跨环境稳健"的强主张。
4. **oracle 的适用边界**：oracle 是评测上界，读隐藏时长，**不可部署**；它只回答"有没有可能"，不回答"能否学会"。
5. **模型保真**：oracle 假定单工人单路径、无重访，与引擎一致；若引擎语义再变（如 release 语义），需重新验证（本单元已用 DP/穷举/MILP/引擎回放四方对齐来降低此风险）。
6. **时长独立性**：隐藏时长按 family 独立取样，未建模同环境内相关性；若真实数据存在环境级相关，oracle 与在线差距的相对大小可能变化。
