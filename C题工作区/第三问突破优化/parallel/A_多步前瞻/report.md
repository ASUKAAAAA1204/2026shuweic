# 角色 A：正确多步前瞻（深度 2–3）实验报告

## 交接摘要（约 150 字）

本单元把一步前瞻的贪心尾部替换为深度 2–3 的正确期望前瞻：时钟推进到完成时刻 `start+p`，链式完成概率按祖先门控，预算先筛后选，分位网格明确为离散近似。所有数字来自本目录 `results/` 的 trials.csv，并与 baseline、审计修正版、v2（祖先门控 depth-1）在同案例、同种子、同映射上配对。结论：深度 2/3 在标称与五映射上均未超过 depth-1；depth-1 在验证集 +5.15pp，但环境留出为负。角色 A 的可检验假设被否定，**未达 6% 验收门槛，不能称突破**。

## 1. 假设与评测协议

### 1.1 待检验假设

原 lookahead 的结构性近似是「顶层一步精确、尾部退化为按期望时长的贪心推演」。角色 A 的假设是：**尾部贪心是主要损失来源**，因此把尾部换成深度 2～3 的期望前瞻，应能突破 6% 相对目标（标称 ≥ 90.198%）。

### 1.2 协议（原样复用，保证可合并）

- 案例 S1/S2/S3；30 个 validation 种子（`cond["validation_seeds"]`）；5 种映射 (α,β) ∈ {(1,.5),(.75,.5),(1.5,.5),(1,0),(1,1)}。
- 每个 (案例, 种子, 映射) 上 baseline 与候选方法配对运行。
- 隐藏时长逐字复用 `confirm_lookahead.py` 的 `hidden_for`：`rng=random.Random(seed)`，按 `jobs_for(tasks, case_id)` 顺序，对每个 job 在 validation & eligible 池中按 family 取样；未改变遍历顺序。
- 计分使用正式 `engine.Engine`，并用 `engine.independent_metrics` 复核；断言无非法动作且最大差 < 1e-9。
- 时长拟合只用 train 划分；validation 只用于模型选择；未读取 test 划分。
- 实例内反馈：记录 `d_hat = (completion - service_start - β)/α`，按 family 累积。
- 决策不读取隐藏时长、案例号、目标值；α/β 由 `observe()` 公开，合法使用。
- 预留固定 0.2 秒。

### 1.3 审计缺陷的落实（禁止重复）

| 审计项 | 本实现的处理 |
|---|---|
| P1 尾部时钟重复计入移动/准备 | 状态时钟推进到完成时刻 `start+p`；下一步的 `start` 再加 `D+0.5` |
| P1 链式概率乘全部前序路径 | 每个任务只乘**其祖先链**的完成概率；并行分支互不惩罚；未在 H 内完成的任务不解锁后继 |
| P2 预算在选择后检查 | 候选先做预算可行性筛选，再按价值排序；尾部不会因选中超支任务而中止 |
| P2 128 点网格非精确 | 文档与报告统一称「离散近似」，不再声称精确保留任意混合权重 |
| fb=0 语义 | `feedback_strength <= 0` 明确为「不使用反馈」，只用先验 |
| 完美信息 93.77% | 不引用、不作为上界 |

## 2. 方法

### 2.1 决策目标

在状态 `(t, xy, done, remaining, cost)` 上求

```
V(t,xy,done,remaining,cost) = max_j E_{p_j}[ 1{j 按时}·w_j + V(t',xy_j,done',remaining\{j},cost') ]
```

其中 `t' = min(H, start+p_j)`；仅当 `start+p_j ≤ H` 才令 `done' = done ∪ {j}`（截尾任务不解锁后继）。所有分支先做释放、前驱、时域与预算可行性筛选。

- 顶层对每个可行候选做 `nq_root=5` 个分位积分，**不是**中位数单场景。
- 第 2 层对**全部可行后继**做期望评估；仅在非根层按「即时值 + 贪心尾部」上界排序后保留前 K（束宽）个，K ∈ {4,8,16}。
- 叶子（深度耗尽）为期望时长贪心推演，逐任务按祖先链完成概率门控。
- 时长信念：族经验分布 → 全局先验收缩（strength）→ 实例内反馈收缩（feedback_strength=3），128 点离散分位近似；判定前先做 `p = αd + β` 映射。

### 2.2 代码

- `code/multi_step_policy.py`：`select(...)` 与递归 `_value(...)`、叶子 `_greedy_tail(...)`。
- `code/run_multistep.py`：配对评测（产出 trials.csv / summary.json，含每个方法的耗时）。
- `code/holdout_multistep.py`：环境分组留出。

## 7. 局限

- 验证集只有 3 个案例，标称三案例等权均值的案例级方差大；bootstrap 区间按种子重采样，不覆盖参数选择偏差。
- `v2` 的 strength=20 与深度/束宽是在同一开发集上挑选的，表中的点估计不是无偏效应；`d2b*/d3b*` 参与了多轮试探，选择偏差同样存在。
- 深度 2/3 的计算量是 depth-1 的数十倍，在本工作区 CPU 共享条件下耗时读数只用于同批比较。
- 叶子始终是贪心推演：深度只把「精确期望」向前推 2～3 个任务，剩余 5～13 个任务仍在贪心尾部内，因此深度增加并不能消除尾部近似。
- 未读取 test 划分；未修改正式方案与其它并行目录。
