# 角色 E：稳健时长分布与选参（第三问调度优化并行工作单元）

**交接摘要（约150字）**：角色 E 把决策核心固定为修正版一步期望前瞻，只改时长信念与选参。信念=环境均衡分层收缩（族池每环境等权→环境均衡全局先验，strength=40，不做截尾，反馈强度 3）。23 个候选只用两组环境 CV 选参，验证集只确认一次。验证标称 90.4514%（+5.359pp，95%CI[3.81,6.90]），五映射均值 88.5741%，逐映射均高于基线；两组环境留出 +1.65pp（+0.21/+3.09）。验证选择偏差估计 +1.56pp（CI[−2.64,+4.38]），超出 6% 阈值的余量仅 0.25pp，稳健性有限。

## 1. 假设

- **H1（增益来源）**：v2 的增益主要来自时长分布估计与参数选择，而不是更复杂的决策搜索。若为真，则在决策核心完全固定的前提下，仅替换信念就能复制或超过 v2。
- **H2（跨环境不稳的来源）**：族池被单一环境主导。训练集 family A 共 112 条，其中 `retail_x_supermarket_0058` 一个环境占 28 条；L 族只有 10 条、分布在 2 个环境。按样本直接池化时，留出环境一旦正是主导环境，族分布会系统性错位。
- **H3（二阶项）**：实例内反馈、尾部 Winsorize 属于二阶修正：预期反馈有正贡献，Winsorize 未必。

## 2. 方法与合法信息边界

### 2.1 决策核心（全部候选共用，不参与选参）

`robust_chain_policy.select` 固定采用审计修正后的一步期望前瞻：

```
score(j) = mean_{q∈5} [ 1{j 按时}·w_j + greedy_tail(t = start + p_j(q), zone_j, done∪{j}) ]
```

- 时钟推进到完成时刻 `start + p`，不再重复计入移动/准备（修正 P1 尾部时钟）；
- 尾部的逐任务价值按**祖先链完成概率**门控，并行分支不互相惩罚（修正 P1 链式概率）；
- 预算在建候选时**先筛不可负担任务再排序**，不在选中后终止尾部（修正 P2 预算）；
- 协议细节：预留 0.2 秒；`observe()` 公开 α/β 并合法使用；不使用隐藏时长、案例号、目标值或付费观测（本实验中 `observations=0`）。

### 2.2 时长信念（本单元的处理变量）

三层结构，全部只用 train 划分：

1. **族层**：把每个环境内该族的样本压成 64 点等概率分位支撑；`balance=env` 时各环境等权合并（`pooled` 时按样本直接合并，`region` 时按环境首段域等权合并）。
2. **全局先验层**：同样按环境/区域等权构造，再以 `w = n_f/(n_f+strength)` 把族层向全局层收缩。
3. **反馈层**：实例内 `d_hat=(completion−service_start−β)/α` 按 `n_h/(n_h+feedback_strength)` 收缩进信念；`feedback_strength ≤ 0` 明确表示**不使用反馈**（只用先验），已按审计语义实现。

表示说明：支撑是固定 64 点离散支撑，混合权重是**精确浮点权重**；生存概率在该离散支撑上精确，对连续分布仍是近似。**不声称"精确保留任意混合权重"**。

### 2.3 合法信息与排除项

- `family × case-size` 先验被**主动排除**：三案例任务数正好是 8/12/16，与案例号一一对应，用它等价于读取案例号，违反协议。
- 环境/区域只用于**构造训练先验的聚合权重**，不进入单次决策特征；策略看不到 environment_id。
- 选择规则、候选集合与验证前冻结记录见 `results/selection_decision.json`（含 4 个源文件 sha256）。

### 2.4 参数与选择规则

23 个候选，覆盖 balance×strength、winsor_q、feedback_strength 三个维度（全表见第 4 节）。选择规则在跑网格前声明：

> 最大化两折**环境分组 CV** 的配对平均差；并列时取较差折更优者。validation 不参与选择。

该规则在 `code/freeze_selection.py` 中实现，并在任何完整 validation 运行前写出冻结文件。

## 6. Validation 选择偏差的量化

设计上本单元**没有**用 validation 选参（选择在 `results/selection_decision.json` 冻结后才运行完整 validation）。为回答"如果按 validation 选会偏多少"，做了事后分析（不回流选择）：

- 23 个候选全部在 validation 标称映射上回放（`results/selection_bias/trials.csv`）；
- 30 个种子按奇偶切成两半，在一半上取 argmax、在另一半上评估，得到 split-half 乐观偏差；
- 对种子聚类重采样 2000 次，每次重采样内部重新取 argmax。

结果：

- split-half 乐观偏差：以半 A 选、半 B 评得 −0.02pp（选中 `env_s80_fb3_w95`）；反过来以半 B 选、半 A 评得 +3.15pp（选中 `env_s40_fb6_w95`）；**两者均值 +1.56pp**；
- bootstrap **均值 +0.80pp，95%CI [−2.64, +4.38]**；
- CV 选中配置在 validation 上排第 5（90.4514），距 validation 最优 `env_s80_fb3_w95`（90.7060）仅 **0.2546pp**；23 个候选整体极差 2.014pp。

**解读**：本方法的 validation 点估计 90.4514 只比 6% 阈值高 0.253pp，而 validation 选参的典型乐观量是 0.8–1.6pp，因此"超过 6%"不能被当作稳健结论；它的正确表述是"在预先冻结的单一配置上、一次性确认达到门槛"。另有一条反向证据：validation 第 3 名 `pooled_s20_fb3`（90.6134）在环境 CV 上是 −1.69pp、折0 −6.68pp；若按 validation 选参就会选中一个换环境即崩的配置，这正是不能用 validation 选参的原因。另有两条已披露的验证前兼容性检查（v2_s20、pooled_s20_fb3 的标称复跑），它们不参与选参，但意味着 validation 并非完全盲测。

## 7. 失败分析

- **pooled 族先验在折0 崩掉（−6.68pp）**：折0 留出的环境组包含 family A 的主导环境 `supermarket_0058`（28/112 条），拟合侧失去它后族分布整体偏移；这直接验证 H2。同 strength=40 下 pooled 仍为折0 −4.99、合并 −0.83，改为环境均衡后折0 +4.73、合并 +4.28，差别来自聚合方式而不是 strength。
- **region 均衡不稳**：region 把 4 个域等权，但零售域内部环境异质性最大，s20 时折0 −2.39；只有 strength 提高到 40 才转正（+3.60），说明区域层不足以替代环境层。
- **Winsorize 没有增益**：截尾压缩的正是决定"能否按时"的上尾，90% 截断在折0 只有 +1.52，明显低于不截尾的 +4.73。
- **S1 相对 v2 略降**（97.92 vs 99.17）：S1 只有 8 个任务，单次决策翻转就能移动约 1.25pp 的加权按时率；此处是案例级方差，不是系统性退化（相对基线仍 +4.58pp）。
- **v2 复跑差 0.08pp**：无法在现有工作区核对 A 组当时的逐次结果（没有归档 trials），只能记录差异并采用自己的复跑值。
- **`family × case-size` 路线被否决**：任务数与案例号一一对应，属案例号泄漏，未实现。

## 8. 局限

1. **选参与留出共用两组环境**：留出只换了种子，环境层泛化未验证；组0 +0.21pp 说明这种泛化很容易消失。
2. **CV 点估计本身是 23 选 1 的最大值**：两折 16 个聚类不足以估计 CV 层的 winner's curse；已给出候选全表与验证侧偏差区间作为替代证据。
3. **网格是在第一轮 CV 后围绕最优方向加密的**（env 轴与 feedback 轴），属自适应扩展；它未接触 validation，但会放大 CV 点估计的乐观量。
4. **信念是 64 点离散近似**：生存概率在支撑上精确、对连续分布近似；与 v2 的 128 点网格混合同样不可比"精确"。
5. **反馈样本存在选择偏差**：只有完成任务的实测时长进入反馈，被截尾任务不产生反馈；`feedback_strength` 越大，这一偏差越被放大。
6. **不是全局最优，也没有理论保证**；测试划分全程未读取。
7. 三案例 × 两组环境是本任务的硬边界；任何"跨环境稳定"的结论都超出当前数据能支持的范围。
