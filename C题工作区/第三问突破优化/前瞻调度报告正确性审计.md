# 前瞻调度报告正确性审计

审计对象：`前瞻调度_验证集突破与留出结论.md`。
审计范围：报告数字、配对评价、决策实现、留出解释和可复现来源。
审计结论：**原报告的运行汇总数字基本算术正确，但其“风险积分前瞻”实现有时钟和链式概率错误。90.80%确实能由原代码复现，却不能作为修正后方法的质量结论；原6%相对突破结论不成立。**

## 2. 报告中的数值核对

从`results/lookahead_validation/trials.csv`重新计算得到：

- 基线标称三案例等权加权按时率：85.0926%。
- 原lookahead实现：90.7986%。
- 绝对差：+5.7060个百分点；相对改善：+6.7057%。
- 分案例差：S1 +5.625、S2 +8.472、S3 +3.021个百分点。
- 30个种子中26个案例平均配对差为正。
- 五映射总体差：+3.6991个百分点；分别为+2.5926、+3.4375、+5.7060、+4.2824、+2.4769个百分点。
- 原脚本按种子簇重采样的95%区间可复现为约[+4.26,+6.99]个百分点。它是**给定当前案例和所选配置后的种子区间**，不含强度筛选和多轮验证试探的选择偏差，也不估计案例/环境总体变异。
- 900行均无非法动作，独立计分差最大1.14e-13。原运行本身的程序与计分记录可靠。

因此，原文件报告的是**原代码的真实回放结果**；错误在把它解释为无缺陷的前瞻算法证据以及把该分数当作无偏的方法效果。

## 3. 关键实现错误

### P1：尾部时间重复计算路程

原文件`code/lookahead_policy.py`的`_tail_value`中，`start=t+D+0.5`已经把从当前位置到任务区的移动和准备时间计入服务开始时刻；`occ=D+0.5+mean(p)`又是从当前决策状态起算的总占用。随后用`start+occ`判断时域，并令` t=start+occ`，将移动与准备时间再次计入。

对于任务j，若`start`是服务开始、`p`是服务时长，则完成时刻应为`start+p`；后续状态时钟也应前进到该完成时刻。原代码却使用`start+D+0.5+p`。这会系统性地压低尾部价值，并改变首任务选择，不是单纯计算耗时的展示错误。

### P1：对后继链把概率事件当成确定完成

尾部给任务j贡献`w_j P(j按时)`，随后无条件把j加入`done`并完整解锁后继。若j未在时域H内完成，其后继不能执行；多层链的收益应乘以前序全部成功完成的联合概率，或在场景树中分别模拟成功与失败。原实现既未传播`P(j在H内完成)`，也未分支失败状态，可能高估闭合链的价值。

### P2：尾部预算可行性在选择后才检查

尾部先按密度选最高价值任务，再扣费；若该任务超预算就直接结束尾部，不尝试次优但仍可负担的任务。这可能低估某些候选的尾部价值。单独只修该项，在本验证队列平均结果无可测变化，但逻辑应修正。

### P2：固定128点分位网格不能“精确保留任意混合权重”

代码先将先验比例乘128并取整。strength=40、训练样本量A=112/L=10/P=124时，目标先验权重分别为26.316%/80.000%/24.390%，实际网格权重为26.563%/79.688%/24.219%。差异不大，但原模块文档的“每个混合权重精确保留”不正确；反馈权重同样会被量化。应改称离散近似，或采用可带权的经验分位网格。

## 4. 修正后同条件复跑

为避免重写策略造成新的实现偏差，审计副本由原文件机械复制，只增加独立开关控制时钟、链式完成概率与尾部预算修正。`clone_original`与原实现630次配对回放逐案逐种子完全一致，最大差0，证明消融副本在关闭修正时复现原策略。

| 实现 | 标称加权按时率 | 相对基线差 |
|---|---:|---:|
| pressure_gated | 85.0926% | — |
| 原lookahead | 90.7986% | +5.7060 pp |
| 仅修正尾部时钟 | 89.0509% | +3.9583 pp |
| 仅传播链式完成概率 | 90.5324% | +5.4398 pp |
| 仅尾部预算可行筛选 | 90.7986% | +5.7060 pp |
| 三项均修正 | 89.9884% | +4.8958 pp |

修正后相对改善约5.753%，低于6%相对目标；绝对提升4.896个百分点，也低于6个百分点目标。修正版加权完成率94.65%，相对基线94.07%；无非法动作，独立计分最大差5.68e-14。

修正版五映射都高于基线，但结果不能再引用原90.80%和+6.71%。原配置strength=40是此前在相同开发集上从20/40/60中选出；修正版数字只用于核验逻辑错误的影响，不是新独立验证。

在预先使用的两组训练环境压力留出上，原实现平均差约+0.10个百分点，组间为−3.51/+3.72；使用严格复制式修正版后约+1.34个百分点，组间为−1.61/+4.29。该试验仍只有两组且沿用验证集选出的strength，属于环境压力测试，不是独立泛化证明。

## 5. 其他报告表述

- **“fb=0去掉反馈”错误**：`_mixture`在已有历史且`feedback_strength<=0`时直接返回历史样本，表示完全采用反馈，不是移除反馈。真正无反馈消融应始终向策略传空历史或单独禁用历史更新。原89.47%即使能复现，也不能归因于“没有反馈”。
- **基线描述不完整**：原pressure_gated在拥塞时已含当前按时概率、延后机会损失和直接后继补偿；非拥塞才用density。不能把它整体写成`w·P/(移动+准备+中位数)`，也不能说它完全只使用点估计。
- **所谓完美信息上限存在直接矛盾**：原报告S1完美信息值98.75%低于同实例可执行原lookahead的98.96%。若抽样及约束完全相同，真正最优完美信息上界不可能低于某合法策略的均值；需提供逐实例证据并更名为启发式参考，或证明采用了不同协议。


- **strength扫参表**：工作区原先没有独立扫参脚本/原始CSV；本次重新按同一验证样本复算，原实现20/40/60得到89.8032%/90.7986%/89.9421%，与报告四舍五入值相符。由于在该验证集选择40，成绩有选择偏差。
- **消融表**：原始文件没有配套消融trials、脚本或seed级表，报告中的87.28/89.47/90.43暂属未独立核实数字；引用前需要补做配对复算。
- **完美信息93.77%**：项目内没有找到生成代码、逐实例结果或上界证明。若是启发式oracle，它只能给出可行值，不自动构成完美信息最优上界。该数值目前不可引用为已核实上限。
- **验证集选择许可**：验证集可以按题意用于选模型；但经过多轮候选及强度搜索后，所报告的区间不再是未选择的确认性推断。需称“既有开发集模型选择结果”。
- **全局最优/泛化**：原文件没有证明全局最优；两组环境留出分歧明显，也没有证明跨环境稳定提升。

## 6. 最终判断

这份文档**不能按现状作为无保留的算法正确性结论提交**。可保留原代码90.80%作为“历史实现的回放结果”，但必须同时披露实现缺陷。若论文要声称前瞻方法的有效增益，应以修正实现重跑结果为准：当前标称89.99%，相对基线+5.75%，并披露开发选择偏差和环境差异。

该结论不否定“前瞻调度可能有效”；它否定的是目前报告中将90.80%归因于数学上正确的尾部前瞻，以及据此宣称6%提升已稳健达成。
