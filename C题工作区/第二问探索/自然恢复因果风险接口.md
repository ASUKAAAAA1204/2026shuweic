# 自然恢复风险接口：因果性修复与校准限制

本轮发现并纠正一项部署边界：过去恢复校准按当前帧是否事后确认恢复来分组，适合诊断，但在当前帧到达之前不能作为在线选择半径的标签。原统计数值保留，解释限定为事后分层，不冒充因果在线校准。

## 实现

新增RecoveryTracker，仅receive收到的采样时间、到达时间、有效性及合格位置可以改变状态。predict只使用已经接收的信息：

- uninitialized：尚无合格观测，无可用预测。
- missing：已知标坏或观测超龄，继续传播旧状态，但不认证容差。
- recovered_single：已收到一个恢复合格点，更新起点并衰减旧速度；不假定新瞬时速度已知。
- tracking：收到连续两合格点，可重新估计速度。

首帧到达前仍为missing（或此前尚未收到坏标记时的既有状态），不使用未来的first标签。迟到样本保留采样年龄；重复、未来采样时间和逆序到达拒绝。间隔阈值在训练回放使用该记录原始中位采样间隔的3倍，这是用于流连续性判断的回放约定，不是物理安全参数。

所有不确定性状态默认uncertified。只有显式提供已支持的经验半径和容差，且处于tracking，才可输出empirical_within/empirical_exceeds；reliable_guarantee始终false。因此“无法认证”不会被删去或记成安全。该接口修复的是虚假确定性与状态机，不自动提高位置准确率，也不替代最终可靠性校准。

## 验证

11项边界检查通过，包括单帧/双帧恢复、坏标记到达前后、延迟首帧、重复样本、未来样本及过龄拒绝认证。完整55训练记录、94092个手别时刻回放，每次先预测再接收当前质量和位置，保证当前参考/当前标记不先进入预测。开发和测试读取0，原正式模型保持。

结果：results/recovery_interface/audit.json、causal_modes.csv.gz、mode_counts.csv；实现code/recovery_interface.py；复核code/verify_recovery_interface.py。

## 仍未解决

1. missing和recovered_single的经验半径需按因果前状态校准，不能把事后first标签直接当作部署输入。
2. 只有恢复期少量合格参考，无法为全部missing内部建立真误差保证。未合格当前帧的预测仍不得用其坐标算真误差。
3. 标记模式与不认证输出不意味着任务精度目标已经达成。需要同时报告各模式可服务比例和实际合格参考覆盖。
4. 付费单点返回有不同延迟与载荷，本自然流接口不能静默覆盖原付费模式。

下一步可用本接口的pre_mode与合格参考建立因果模式校准，再按整个训练环境留一核验。整个第二问已知问题目标仍在进行，不能以状态机正确替代严格容差、成本和泛化目标。
