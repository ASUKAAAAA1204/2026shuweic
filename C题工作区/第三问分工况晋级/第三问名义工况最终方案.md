# 第三问名义调度最终方案

采用 S1、S2 逐任务优先级调度与 S3 滚动调度。对照为提交 `c6a63a5` 已采用的截止机会损失调度器 `pressure_gated`。名义映射为 α=1、β=0.5。旧版和新版同一工况、同一种子使用完全相同的任务及服务时长。

## 策略与淘汰过程

- **S1、S2** 分别用训练任务族区间模拟调度，搜索每个公开任务的优先级以及紧迫度、超期、移动和单位时间收益系数。运行时每次根据当前时刻、所在区域、剩余预算、任务释放和前驱完成情况重新排序，选择可执行任务。两工况各自的参数与执行代码从第一轮起锁定。[S1 参数](results/round_1/S1.json) · [S2 参数](results/round_1/S2.json)
- **S3** 每完成一项任务，就把已实现的服务时长还原为该任务族的一次观测，与训练先验合并。每次决策为各待选任务生成 64 组分层抽样时长，比较多种合法顺序，执行最佳顺序的第一步。滚动搜索使用四个起点，每个起点最多 75 次顺序调整，完成收益系数 0.12，训练先验的等效样本数为 1。计划预留 0.2 秒。[S3 参数](results/round_4/S3.json) · [滚动目标与顺序搜索](rolling.cpp)

|S3 候选|30 种子按时率|30 种子完成率|120 种子按时增益|结论|
|---|---:|---:|---:|---|
|第一轮，任务优先级|77.92%|92.60%|−1.54 个百分点|按时率两项未达标|
|第二轮，使用训练先验，关闭实例反馈|83.02%|92.71%|−0.44 个百分点|附加种子退化|
|第三轮，24 场景滚动计划|81.77%|91.25%|+1.12 个百分点|登记按时率偏低|
|第四轮，64 场景分层滚动计划|82.60%|91.67%|+2.63 个百分点|通过|

第四轮训练复选包含两个留环境组各 20 次和全训练池 40 次，三个组等权。实际脚本在不同来源池中复用了前 20 个种子编号，因此这三组共 80 次回放，共有 40 个不同编号。最后的 240 个确认种子与这些训练编号互不重叠。

仍有研究空间，主要在 S3 的按时率与移动成本。现有搜索一旦发现可行任务就选择执行；可在其他验证来源上检验「主动等待即将释放的高权重任务」能否同时减少拖期与额外移动。该设想尚无本轮实测结果。

## 复现与调用

Windows 下需要 Python、NumPy、pandas 和 PATH 中可用的 C++17 MinGW g++。从集成仓库根目录执行下列命令，用冻结模型重放旧版与新版，逐项对照旧版官方归档和晋级时的成绩，并从动作日志独立重算指标。

```powershell
python -B -X utf8 "C题工作区/第三问分工况晋级/confirm.py"
```

线上每个回放实例新建一个 `NominalDispatcher(case)`。每步传入模拟器公开观测调用 `choose`，仅在任务成功完成时调用一次 `record_completion(family, service_start, completion)`。输入采用对应的官方任务表和任务 ID 顺序。执行策略看不到回放种子、区间编号和未实现时长。非名义映射沿用上一版调度路线。[统一调度类](final_solution.py) · [确认回放](confirm.py) · [三问统一入口](../正式方案/code/run_all.py)
