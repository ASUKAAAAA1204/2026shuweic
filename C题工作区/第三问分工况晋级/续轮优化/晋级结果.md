# 第三问续轮优化结果

S1 沿用冻结版本。S2 和 S3 各提交 5 轮候选，S2 第 5 轮晋级一次，S3 第 3、5 轮先后晋级两次。第 5 轮后停止搜索。每轮每工况从开发组选择一份参数，内部的参数组合数不计作优化轮数。比较起点为上一版分工况调度。

## 最终调度与复现

S1 直接调用上版冻结的任务优先级调度器。S2、S3 每次从训练任务族的时长分布和已完成任务的实际服务时长构造 32 组假想时长，同时评估多个可行任务顺序，允许等待任务释放。两者都只执行选中路线的第一步。S2 每层最多保留 48 条路线，S3 保留 64 条。临近总时限时，提高完成任务的评分权重，两者的时长先验均采用训练分布与实例反馈。最终策略的前缀权重为零，全部回放中付费复核次数和非法动作均为零。

运行环境为 Windows、Python、NumPy、pandas 及可在 PATH 访问的 C++17 MinGW g++。在集成仓库根目录运行：

```powershell
python -B -X utf8 "C题工作区/第三问分工况晋级/续轮优化/verify_release.py"
```

正式调用为 `release.dispatcher(case)`，每个实例单独创建控制器，传入公开状态调用 `choose`，成功执行后调用 `record_completion`。核验脚本从各轮明细重算门槛，从已发布入口重放起点、一级与二级，核对官方逐种子归档、来源抽样和最终动作。S1 的参数与执行文件沿用原锁。[冻结清单](freeze.json) · [调度入口](release.py) · [核验结果](results/final/audit.json)
